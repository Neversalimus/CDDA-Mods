# Работа в нескольких чатах

Источником истины служат файлы репозитория и принятые коммиты. Память чата и старый
ZIP не должны молча заменять актуальную версию.

Стартовый запрос:

> Работаем с Neversalimus/CDDA-Mods. Прочитай AGENTS.md и docs/STATUS.md,
> обнови сведения о remote HEAD. Задача: [изменение]. Моды: [IDs]. Игра: [точный
> tag/commit]. Создай отдельную ветку/worktree. Не изменяй NCMM и другие моды.
> До изменения покажи найденные версии; после — diff, проверки и handoff.

Если GitHub недоступен в конкретном чате: передать ZIP исходников + результат
`python tools/modsuite.py context --mods ...`. Это переносимая точка входа.
Не обещать, что ссылка сама подключает GitHub к любому чату или телефону.
Если доступа к записи нет, подготовить патч/архив и назвать базовый commit.

Два чата могут одновременно менять разные моды в разных ветках. Каталог релиза,
общий установщик и один и тот же мод — общие точки конфликта. Их изменения
объединять через PR после обновления от main. Не редактировать одну общую рабочую
папку двумя чатами. Не делать force push.

Перед завершением каждого этапа обновлять:
- changelog изменённого мода;
- docs/STATUS.md — только подтверждённое состояние;
- docs/HANDOFF.md — задача, ветка, commit, точная игра, файлы, тесты, ограничения,
  следующий шаг и местонахождение отчётов.

Проверка актуальности перед релизом: повторно сравнить выбранные исходники с
новыми архивами/ветками, если параллельно велась разработка. Зафиксировать точку
среза. Новые версии не подменять старыми DLL или патчами от другой базы.
